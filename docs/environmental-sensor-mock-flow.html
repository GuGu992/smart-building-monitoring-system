Mock workflow

Offline → Maintenance → Approval → Online

Offline1. Admin marks offlineConnection becomes Offline, condition is cleared, UI shows 0, and a Sensor Offline alert is created.
→
Open2. Maintenance workAdmin creates/assigns maintenance. Staff starts work, records notes, then submits completion.
→
Pending3. Admin reviewApproval is transactional. Rejection keeps work open; approval completes the repair.
→
Normal4. Sensor recoversConnection becomes Online, a normal reading is stored, related alerts clear, and charts continue with history intact.
State rules

Condition evaluation

  • Temperature: up to 3°C outside range = Warning; beyond 3°C = Critical.
  • Humidity: up to 10 percentage points outside range = Warning; beyond 10 = Critical.
  • AQI and energy use the Admin-configured Warning and Critical limits.
  • Automatic readings use small random walks; 8% are Warning and 2% are Critical.
  • Offline is a connection state, never an environmental condition.
  • Offline metrics are stored as null chart gaps while the current UI displays 0.
This wireframe documents the implemented flow; it does not replace or redesign the application templates.
